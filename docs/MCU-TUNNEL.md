# 给单片机中继加密：用 WireGuard，别自己写协议

## 为什么

中继那台（单片机旁边的常开机）现在把数据**明文**发到中枢。两种改法：

| 做法 | 评价 |
|---|---|
| 给中继加 TLS / 自己拼一套加密 | ❌ **不建议**。证书签发/固定/续期都得自己管，而且只保护一条连接；自研协议最危险的地方在于"看着安全" |
| **打一层 WireGuard 隧道**（本方案） | ✅ 整条链路加密：中继到中枢的**所有**流量（含重试、补发、别的端口）都自动走隧道；实现经过大量审计；配置一次几乎不用再管 |

> 补一句公平话：如果中继那台和中枢**本来就在同一个可信局域网**，那这层可以不做 ——
> 威胁模型不同，别为了"看起来更安全"给自己加运维负担。

## 三步搞定

**① 中枢那台（公网，服务端）**
```bash
sudo bash hub/tools/mcu_tunnel_setup.sh server
```
它会生成密钥、写好 `/etc/wireguard/wg0.conf`、起好服务，并打印**对端公钥 + PSK**。

**② 云安全组放行 UDP 51820**（入方向）
这一步只能点控制台 —— 隧道不通 90% 是这里忘了。

**③ 中继那台（客户端）**
```bash
sudo bash hub/tools/mcu_tunnel_setup.sh client <对端公钥> <中枢公网IP> <PSK>
```
然后把打印出来的**客户端公钥**填回服务端配置里的 `REPLACE_WITH_CLIENT_PUB`，重启隧道：
```bash
sudo wg-quick down wg0 && sudo wg-quick up wg0
```

## 连上之后

中继**代码不用改**，只把上报地址从公网 IP 换成隧道内地址：
```
http://10.66.66.1:11440      # 原来是 http://<中枢公网IP>:11440
```
其他一切照旧（`X-Token` 鉴权、序号 + 校验和、失败补发都不变）。

## 三个必须知道的点

1. **隧道 ≠ 鉴权**。它只保证"链路是加密的"，不代表"来的人是谁"。`X-Token` 仍然要留、仍然要够长。
2. **密钥不许进仓库**。`/etc/wireguard/` 下的东西（`*.key`、`psk.key`、`wg0.conf`）都在本机，
   权限 `600`；仓库里只有这个脚本和文档。
3. **PSK 是额外一层**：即使将来某天公钥算法出问题，预共享密钥仍然挡着（多一层成本几乎为零）。

## 排查

```bash
sudo wg show                     # 看 latest handshake 有没有数据
sudo wg-quick down wg0; sudo wg-quick up wg0
ping 10.66.66.1                  # 客户端 ping 服务端隧道地址
curl -s -H "X-Token: $TOKEN" http://10.66.66.1:11440/health
```
`latest handshake` 一直空 → 九成是安全组没放行 UDP，或者服务端没登记客户端公钥。
