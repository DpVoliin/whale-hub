# 威胁模型（Threat Model）

> 外部评审 v3 的第 3.5-5 条说："没有 threat model，安全特性就无法被验证与审计。" —— 这份文件补上。
> 写法：先划**信任边界**，再逐条列"谁会怎么打 → 我们怎么防 → **还剩多少风险**"。
> 最后有一节"**我们不防什么**"—— 那一节和前面同等重要。

---

## 1. 要保护的东西（Assets）

| 资产 | 为什么敏感 | 存在哪 |
|---|---|---|
| 采集到的原始数据（屏幕/应用/健康/日程/订单原文） | 能还原一个人的生活全貌 | 中枢 `hub.db`（本机 SQLite） |
| 中枢 token / 单片机 token / 配对码 | 拿到就能读数据、灌假数据、删除数据 | `hub.json`（600） |
| 模型 API key | 花钱 + 能冒名调用 | **只在说话层那台机器**上，中枢碰不到 |
| 私钥（TLS） | 拿到就能中间人 | 服务器本机生成，`chmod 600`，**永不外传** |
| 审计链 | 事后追责的唯一依据 | `audit` 表（链式 hash） |

## 2. 信任边界（Trust boundaries）

```
① Android 采集器 ──HTTPS(证书固定)──▶ ② 中枢(non-root 可达? 见下)
② 中枢 ◀──HTTPS(自签)──▶ ③ 你自己的终端（挂件/网页/手机浏览器）
② 中枢 ◀──明文(仅内网)──▶ ④ 内网中继 mcu_relay ──明文一行──▶ ⑤ 单片机/小屏
① 中枢 ──HTTPS──▶ ⑥ 分发服务器（只发 pub/ 白名单）
② 中枢 ──HTTPS──▶ ⑦ 模型 API（只发脱敏后的上下文）
② 中枢 ──HTTPS──▶ ⑧ 微信网关 / 直发出口（企业微信或你自己的 webhook）
```

**边界即信任假设**：①②③⑥⑦⑧ 之间的传输都要求 TLS；④⑤ 明确**不信任**（内网明文、无 TLS 能力），
所以它们的能力被压到最小（只需一个设备 token，只能读提醒、写一行传感器值）。

## 3. 逐个对手（Adversary → 威胁 → 缓解 → 残余风险）

### A. 互联网上的随机扫描器
- **威胁**：扫到开放端口 → 试默认口令、发恶意 payload、勒索。
- **缓解**：只暴露 HTTPS 端口；`X-Token` 头鉴权（不接受 query token）；1 MB body 上限；
  每来源 240 次/分限流；错误响应不回服务端路径；明文端口不对公网开放。
- **残余**：若你把 token 泄露到公开仓库/聊天里，扫描器拿到即可读写（**这正是 2026-09-22 真实发生过的事** —— 已通过轮换 + 推送前脱敏体检解决）。
- **可验证**：`tests/` 的鉴权/注入用例；`docs/PRIVACY.md` 记录的自测 22 项。

### B. 拿到数据库文件的人（偷硬盘 / 云主机快照 / 备份同步到云盘）
- **威胁**：SQLite 是明文的，拿走即全部历史。
- **缓解**：`hubctl backup/dump --encrypt`（AES-256）；文档建议 LUKS / gocryptfs 整盘加密；
  `privacy.retention_days` 默认 365 天自动清理。
- **残余**：**默认就是明文** ✗ —— 这是有意的取舍（本地优先、可 `sqlite3` 直接查）。
  采用了加密才安全，没采用就不安全。我们不做"假装加密了"。
- **可验证**：`hubctl backup --encrypt` 后 `--decrypt` 能还原；错口令报错。

### C. 被篡改的采集端 / 设备
- **威胁**：改过的 App 或单片机，上报任意内容（含伪造的健康/位置）。
- **缓解**：应用层脱敏只保证"给模型的那份"干净；设备只能写自己的指标；
  单片机走独立 token + 校验和 + 序号（`s=`/`c=`）；中继拒绝不校验证书的连接。
- **残余**：**无法根除** ✗ —— 客户端在你手里，它说什么我们只能记录。分析层能做的是
  用"相对自己历史"的方式发现异常（这恰好也是异常检测的用途）。
- **可验证**：`hubctl devices` 能看到来源与最后活跃；`/llm-preview` 能核对进模型的内容。

### D. 恶意/写坏的扩展（`hub/ext/`）
- **威胁**：扩展是**在进程内 import 的 Python**，没有沙箱 → 能做任何事。
- **缓解**：扩展是"你自己的代码"（不是从网上自动下载的插件）；加载失败只打印不影响启动；
  `ext_error` 会进审计。
- **残余**：**没有沙箱** ✗ —— 不引入沙箱是有意的（零依赖 + 单文件，沙箱要额外机制）。
  结论：**只装你自己看过的扩展**。

### E. 模型 API 提供方
- **威胁**：把上下文用于训练、或泄露。
- **缓解**：进模型的一切先过脱敏关卡（`/llm-preview` 可核对）；坐标/应用名/标题/原文一律不出；
  密钥不进中枢。
- **残余**：脱敏后的**语义**仍会到达提供方（"今天屏幕 9 小时"这类）✗ —— 这个无法消除，
  只能由你选择用哪家（也可以换成完全本地模型）。

### F. 物理/本机攻击者（能登录那台机器的人）
- **威胁**：读 `hub.json`、读库、改审计。
- **缓解**：文件权限 600；审计链能**发现**改动；启动日志里的 token 已打码。
- **残余**：能改库的人**也能重算整条链** ✗ —— 链是"篡改侦测"不是"防篡改阻止"；
  真正阻止需要外部存证（另存一份 hash 到别处）。**我们不假装它做到了。**
- **可验证**：`hubctl audit --verify`（篡改一条即报出位置）。

### G. 供应链（第三方依赖 / CI）
- **威胁**：依赖投毒、构建流程被改。
- **缓解**：**运行时零第三方依赖**（这是最强的供应链缓解）；SBOM 自动生成且 CI 自检"依赖项必须为空"；
  Scorecard 每周跑；Dependabot 跟 Actions 版本；发布走 PyPI Trusted Publishing（仓库不存发布 token）。
- **残余**：GitHub Actions 本身是信任的第三方 ✗。

## 4. 我们不防什么（这一节和前面同等重要）

- **不防操作系统/ROM 被攻破** —— 中枢只是普通进程，没有 TEE/SE 的假设。
- **不防你自己把 token 贴到公开的地方** —— 只能提供轮换与脱敏体检（都已提供）。
- **不防云端主机的宿主机** —— 用 LUKS 也只是把风险从"文件级"降到"运行期"。
- **不承诺前向保密** —— 自签证书 + 固定指纹，没有密钥轮换协议（评审 3.1-2 已记入路线图）。
- **不做多租户隔离** —— 一套部署 = 一个人；想给别人用，请各自部署（见 `docs/PRIVACY.md`）。

## 5. 已知缺口（诚实清单，随时更新）

| 缺口 | 影响 | 状态 |
|---|---|---|
| MCU 证书多指纹轮换窗口 | 证书到期即全量失联 | ✅ **已做**（v0.1.23）：`WHALE_PIN` 支持多指纹 + `WHALE_PIN_NEXT` 轮换位，新旧并存 |
| 配对码/登录失败次数限流 | 抗枚举强度 | ✅ **已做**（v0.1.23）：5 次失败/10 分钟 → 锁 15 分钟；成功即清零；只锁该来源 |
| 敏感健康数据的"单独同意"（PIPL） | 面向国内推广时的合规 | ✅ **已做**（v0.1.23）：`consents` 表只追加；入库闸口按同意放行，没同意就丢弃 health.\* 并审计 |
| 备份文件生命周期 | 备份里含全量数据 | ✅ **已做**（v0.1.23）：默认只留最近 7 份（`--keep N` 可调），备份后自动清理 |
