# 本地优先（local-first）：哪些做到了、哪些是取舍

> 对齐 Ink & Switch 的 local-first 七项理想，逐条**诚实**标注。
> 结论先说：**数据主权、离线缓冲、可审计做到了；"无服务器也能用"没做到，那是架构取舍。**

## 七项逐条

| 理想 | 状态 | 说明 |
|---|---|---|
| 1. 不依赖服务器也能工作 | ⚠️ **取舍** | 采集器在断网时把数据**加密排在本地队列**（Keystore AES-256-GCM），联网补发；但"解读与说话"在中枢上。**中枢可以就是你家的一台机器**（4C4G 就够），那它就不算"别人的服务器" |
| 2. 多设备无缝协作 | ⚠️ 部分 | 手机/手表/电脑/单片机都能上报同一中枢；但**没有多端实时同步**（她说话只走一个出口） |
| 3. 离线可用 | ✅ | 采集、入库、规则判断全在本机；只有"生成一句话"和"联网查询"需要网络，失败会**回落模板句**，不漏提醒 |
| 4. 协作 | ❌ 不做 | 个人工具，不做多人共享（明确不做的还有：多租户 SaaS） |
| 5. 数据长期可访问 | ✅ | SQLite 单文件 + `/export` 标准 JSON；删除 = 删文件，不是"注销账号等 30 天" |
| 6. **数据主权**（你的数据你做主）| ✅✅ | 原始数据只在你自己的机器；没有云端副本；不用注册账号；`/export` 可带走，`/erase` 可抹掉 |
| 7. **可审计**（看得见它做了什么）| ✅✅ | `/llm-preview` 列出"会发给模型的全部内容"**且**列出"进模型前剥掉了什么"；`/decisions` 记录每次开口的理由；`hubctl doctor` 体检；代码零第三方依赖、单文件可通读 |

## 隐私红线（写进代码，不靠自觉）

- **进模型前强制脱敏**，`llm_context()` 是**唯一**入口（其他路径拿不到原始数据）
- 位置只用**城市级**（精确经纬度只用于取天气，绝不进模型 —— 这条是被注入式测试抓出来的，见 `tests/test_privacy_injection.py`）
- 密钥不落服务器代码：中枢 token 在 `hub.json`（机器本地），App 端在设置页，说话层在 `.whale_env`
- 传输全程 HTTPS + **证书固定**（App 内置 `hub_cert`，中继默认拒绝无 CA 启动）
- 分发源是**白名单模式**（只对外发 `fx/pub/`）
- 中枢只认 `X-Token` 头 + 1MB 体积上限 + 240 次/分限流（`/api/mcu` 例外，为单片机留 query token）

## 明确不适用（写在前面，省得你白折腾）

- **需要多人共享/团队协作** → 不适合，它是一人一套
- **不想有服务器**（连家里的一台旧电脑/云主机都不想要）→ 不适合，中枢是必须的
- **想在手机上跑模型** → 不打算做（端侧模型明确不做）
- **iOS** → 不在计划内（系统不开放与 UsageStats 等价的接口）
- **健康数据**：依赖厂商 App 往上推通知，**厂商改一次格式就可能断**（README 里写明了这个脆弱点）

## 为什么不做 CRDT / 端到端加密同步

因为**没有多端冲突要解决**：数据是单向汇聚（多设备 → 一个中枢），不是多端协同编辑。
加 CRDT 只会把"单文件零依赖"这个最大优势弄没。这是**有意取舍**，不是没想到。
