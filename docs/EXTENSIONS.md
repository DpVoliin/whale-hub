# 扩展：加一个新数据源不用改核心

中枢是"单文件 + 零第三方依赖"，这既是它的优点，也是一个限制：**不能为了接一个设备就往核心里塞 SDK**。
所以它留了一层外挂：`hub/ext/`。

```
hub/ext/
├── sources/            # 一个 .py = 一个数据源（定时取数）
├── hooks.py            # 可选：在她开口前插一手
└── README.md           # 契约与示例（照着抄就能写）
```

## 为什么这么设计

| 选择 | 原因 |
|---|---|
| **扩展是"文件"，不是"注册接口"** | 放进去就生效，不需要改核心、不需要重启框架里的插件系统 |
| **取回来的数走同一条入库闸口** | 去重、不落原文、单位口径、基线计算、进她的视野 —— 全部复用，新数据源不可能绕过规则 |
| **扩展在自己的线程里跑** | 取数可能做网络 IO；放进 5 秒调度线程里会拖慢她判断的实时性 |
| **任何扩展报错只记日志** | 一个写坏的扩展不该让整台中枢停摆；`GET /ext` 能看到"上次几条、最近一次报错" |
| **核心坚持零依赖** | 需要第三方库的场景交给扩展；扩展由你自己写、自己装，**不进本仓库**（许可证责任也就留在你这边） |

## 数据源契约

```python
NAME = "阳台温湿度"
DEVICE = "balcony"
INTERVAL_MINUTES = 10

def fetch():
    return [{"metric": "env.temp", "value": 26.8, "unit": "C"}]
```

详见 `hub/ext/README.md`（含钩子契约与"能接什么"的对照表）。

## 和另外两条接入路径的关系

三条路径**并存**，按"设备能力"选：

| 设备能做什么 | 用哪条 |
|---|---|
| 能发一行明文（STM32/C51/ESP32/路由器脚本） | `POST /api/mcu`（最省事，不写代码） |
| 能发 JSON 批量 | `POST /ingest` |
| 需要"自己取"（云 API、私有协议、本地文件） | `ext/sources/*.py` |

## 排查

```bash
curl -sk -H "X-Token: $TOKEN" https://<中枢>:11443/ext | python3 -m json.tool
```

改了扩展文件要重启中枢（`rm -f /root/hub/.hubhash` 会在一分钟内触发热重启）。
